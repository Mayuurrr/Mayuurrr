## 🛠 How I work

- **Small, reviewable changes.** I'd rather ship five small PRs than one that takes a reviewer an hour to untangle.
- **Design before code.** API contracts and data models get argued about before the first line is written, not after.
- **Performance is a feature.** Query indexes, memoization, lazy loading — the boring optimizations are usually the ones users actually notice.
- **Tests around the risky parts.** Shared logic, auth, and anything touching money or PII gets covered; UI glue code doesn't need the same rigor.
